Memory systems and reliability budgets

What service does the architecture need from the device?

A nonvolatile cell can be useful for storage without being a drop-in replacement for working memory. The distinction follows from access granularity, latency, bandwidth, endurance, and the controller's obligations. A useful downward analysis starts with those obligations and translates them into device requirements.

Prerequisites: Chapter 5 and elementary probability. Objectives: distinguish memory roles; derive capacity, bandwidth, and error budgets; explain wear management; and specify the protocol implemented by the RTL demonstrator. The 3D ferroelectric-memory architecture review and vertical-NAND perspective motivate the alternatives without making every architecture a demonstrated product.

6.1 Storage, working memory, cache, and compute-in-memory

Storage preserves data across power loss and often operates through block-oriented interfaces. NAND storage can tolerate controller translation, page operations, and maintenance that would be unacceptable on every CPU load. Working memory holds actively accessed program data with a different latency and bandwidth contract. Cache stores copies close to computation and needs tag checks, coherence or explicit software management, and fast frequent access.

Compute-in-memory uses memory structures to perform part of an operation rather than transferring all operands to separate arithmetic units. It changes data representation, precision, sensing, and software mapping. A capacitor that stores a weight, a NAND page that stores a file, and a KV cache serving an autoregressive model therefore need different system designs even if all are called “memory.”

The downward question is concrete: does the workload need rare persistent writes, frequent random updates, sequential weight streaming, or analog multiply-accumulate operations? A technology attractive for one pattern may be unsuitable for another. Evaluate useful bytes or operations per second under accuracy and reliability constraints rather than comparing the fastest isolated device pulses.

6.2 Raw capacity is not usable capacity

If an array has $N_r$ rows, $N_c$ columns, and $b$ bits per cell, raw capacity is $N_rN_cb$ bits. Let $f_{\mathrm{ECC}}$ be the fraction consumed by error-correction redundancy, $f_{\mathrm{spare}}$ by replacement rows or blocks, and $f_{\mathrm{meta}}$ by metadata. If these refer to disjoint fractions of the same raw capacity, usable capacity is approximately $C_u=C_r(1-f_{\mathrm{ECC}}-f_{\mathrm{spare}}-f_{\mathrm{meta}})$. If instead each fraction is defined sequentially on remaining space, multiply factors; do not mix definitions.

Multi-level storage increases $b=\log_2L_s$ for $L_s$ levels, but the resulting narrower margins can require stronger correction and more verify steps. Additional raw bits are not automatically additional usable capacity at the same latency and lifetime. The correct comparison holds the required delivered error rate and service life constant.

6.3 From raw bit errors to protected-word failures

Consider a protected word of $n$ bits with a code that corrects any single-bit error. Suppose independent bits each fail with probability $p$. Let $K$ be the number of erroneous bits. The binomial model gives $\Pr(K=k)=\binom nk p^k(1-p)^{n-k}$. The probability that single-error correction cannot restore the word is

$$p_{\mathrm{uncorrectable}}=\sum_{k=2}^{n}\binom nk p^k(1-p)^{n-k}\simeq\binom n2p^2\quad(p\ll1).$$

The leading approximation retains the first nonzero term. For $n=72$ and $p=10^{-5}$, the project computes $2.55481\times10^{-7}$, close to the leading $2.556\times10^{-7}$. “Uncorrectable” is not necessarily “undetected”: detection capability depends on the code. A 72-bit word suggests a familiar 64-data-bit plus redundancy example, but this probability calculation alone does not implement that code.

Independence is a strong assumption. Shared word-line disturb, supply excursions, radiation events, or correlated process variation can produce multiple errors together. If an event flips a whole row, squaring a small single-bit probability can understate risk severely. Interleaving may spread a burst across protected words, but adds mapping and access consequences.

For $M$ independent protected-word accesses, expected uncorrectable events are $Mp_{\mathrm{uncorrectable}}$. Requiring the probability of any event to stay small can use the union bound $\Pr(\mathrm{any})\le Mp_{\mathrm{uncorrectable}}$, which does not require independence between accesses. Device error targets should be derived from the system's operation count and tolerated failures, not chosen because a laboratory graph looks clean.

6.4 Wear spreading converts lifetime into an allocation problem

Let $N_e$ be an assumed endurance limit in physical stress cycles per location, $N_w$ the number of locations over which writes can be spread, $r_L$ the logical write rate, and $a_w$ the write-amplification factor. The latter counts physical writes, including maintenance, per logical write. Under ideal uniform wear, lifetime is approximately $T=N_eN_w/(a_wr_L)$.

With synthetic choices $N_e=10^6$, $N_w=1024$, $r_L=100$ writes/s, and $a_w=2$, the result is 5,120,000 s. A fixed hotspot receiving all writes reaches the same endurance count in 5,000 s. This thousandfold difference comes from mapping, not improved material. It is an upper-bound allocation example: imperfect spreading, capacity reserved for management, bad blocks, and variable endurance reduce the benefit.

Controllers may remap addresses, maintain counters, perform scrubbing, and verify writes. Their metadata must itself survive interruption and corruption. The delivered small controller intentionally stops before a full flash translation layer; its interface and fault handling are sufficient to expose the device-to-controller boundary without implying enterprise storage functionality.

6.5 Latency and bandwidth are different contracts

If a bank returns a word of $W$ bits every $t_a$ seconds, its ideal payload rate is $W/(8t_a)$ bytes/s. With $B$ independent banks the ideal aggregate is $BW/(8t_a)$. A shared bus of width $W_b$ and clock frequency $f$ caps the delivered rate at approximately $W_bf/8$ for one transfer per clock, before protocol overhead. The usable rate is bounded by the smaller resource rate.

A workload requiring 80 GB/s on a 128-bit single-transfer interface would require 5 GHz with no overhead. A 500 MHz interface of that width instead offers 8 GB/s. More cell-level parallelism cannot cross this interface without widening it, increasing transfer rate, or performing work near memory. Latency also includes queueing; doubling banks does not halve the delay of an isolated access if decoder and wire delays remain unchanged.

6.6 The demonstrator's service contract

The hardware example stores sixteen 8-bit words. A request is accepted on a rising clock edge when both valid and ready are high. The controller latches operation, address, and write data. While busy it ignores requests; the producer must obey the handshake. It produces a one-cycle response two cycles after an accepted read or four cycles after an accepted write.

A fault at the completion boundary produces an error response. A faulted write does not modify the behavioral memory. Reset aborts an in-flight transaction but does not erase previously committed memory contents. These semantics are verified in simulation. They teach protocol and state preservation; they do not model analog write verification, retention loss, a fabricated ferroelectric array, ECC, or power-fail atomicity during an analog pulse.

6.7 Derive the redundancy instead of treating ECC as a label

Our running memory must deliver correct words over many accesses. Error-correcting code, abbreviated ECC, adds redundant bits so a decoder can infer the original data despite some corrupted stored bits. For a binary codeword of length $n$, Hamming distance counts positions in which two codewords differ. To correct every pattern of up to $t$ flipped bits, distinct valid codewords must be separated by at least $2t+1$. Otherwise a received word can lie within $t$ flips of two different originals and unique correction is impossible.

The distance condition gives a geometric interpretation: place disjoint Hamming balls around valid codewords. A ball of radius one contains the original word plus $n$ one-bit variants, so it contains $n+1$ binary strings. If there are $k$ information bits and $r=n-k$ redundant bits, a necessary packing condition is $2^k(n+1)\le2^n$, or $2^r\ge n+1$. It is a necessary counting condition for single-error correction, not a construction of every desired code.

For 64 information bits, seven Hamming parity bits allow $n=71$ and satisfy $128\ge72$. An additional overall parity bit produces the familiar 72-bit extended arrangement with single-error correction and double-error detection under the intended decoder. This explains why the earlier probability example used 72 bits. However, counting errors beyond the correction radius does not say whether they are detected, miscorrected, or passed through. That behavior depends on the actual code and decoder implementation, which the small RTL demonstrator does not include.

Redundancy costs capacity and traffic. A 64/72 code rate delivers eight useful bytes for every nine stored bytes, an overhead of 12.5% relative to data capacity or 11.11% of raw capacity. Both percentages are correct because their denominators differ. A quoted capacity or bandwidth improvement must specify which denominator is used. ECC can also add decoding latency and power, while stronger codes may require iterative decoding or soft information from multiple read thresholds.

6.8 Correlation can dominate the protected-word failure rate

The independent binomial calculation assumed that every bit has the same fixed error probability. A simple model of shared operating variation makes that probability itself random. Let $P_e$ be a latent error probability drawn once per word exposure. Conditional on $P_e=p$, let its $n$ bit errors be independent Bernoulli trials. Unconditionally they are correlated because all bits share the same latent condition. This can represent a common stress or process variable statistically without claiming a specific microscopic cause.

Choose a beta distribution for $P_e$, with positive shape parameters $a$ and $b$. Its density is proportional to $p^{a-1}(1-p)^{b-1}$ for $0\lt p\lt1$. Let $B(a,b)$ denote the integral of that unnormalized density. Integrating the conditional binomial probability over $p$ gives the beta-binomial law:

$$\Pr(K=k)=\binom nk\frac{B(a+k,b+n-k)}{B(a,b)}.$$

The mean bit-error probability is $\bar p=a/(a+b)$. For two different bit-error indicators, their covariance equals $\operatorname{Var}(P_e)$ because their conditional covariance is zero. Dividing by the Bernoulli variance $\bar p(1-\bar p)$ gives correlation $\rho_e=1/(a+b+1)$. Thus mean error and correlation determine the two shape parameters: $a=\bar p(1/\rho_e-1)$ and $b=(1-\bar p)(1/\rho_e-1)$. These are a synthetic statistical family, not an empirical fit to Khan's devices.

Keep $n=72$ and mean bit error $10^{-5}$, but introduce correlation just 0.001. The new laboratory calculation gives probability of two or more errors $2.35716\times10^{-5}$, compared with $2.55481\times10^{-7}$ under independence. The protected-word failure probability is about 92 times larger even though the mean bit-error rate is unchanged. The controller cares about joint failures, not just the marginal histogram.

The calculation uses logarithms of beta functions to avoid overflow and stable subtraction for small probabilities. That numerical care does not make the statistical model true. Validate it by measuring joint errors under shared conditions and compare alternative burst models. A beta-binomial model imposes exchangeable positive correlation; a physical row fault or a particular neighboring-cell pattern can have a different structure. Interleaving can help when it sends physically correlated bits into different protected words, but it cannot remove a common-mode failure affecting all of them.

6.9 Time between repairs is part of the error budget

Consider a stored codeword whose bits accumulate independent permanent flips at a small per-bit rate $\lambda_b$ in s⁻¹. A scrub operation reads, corrects, and rewrites the word, resetting correctable accumulated errors. If the interval between scrubs is $\Delta$, then a bit's error probability before scrub is approximately $\lambda_b\Delta$ when this product is small. For single-error correction, the chance of two errors accumulated in one interval is approximately $\binom n2(\lambda_b\Delta)^2$.

Over a long duration $T$, there are about $T/\Delta$ intervals. The expected count of uncorrectable interval events is approximately $\binom n2\lambda_b^2T\Delta$. Shortening the scrub interval reduces this model's accumulated-error risk linearly. But scrub traffic grows as $1/\Delta$, and each rewrite can consume endurance. This is a genuine cross-stack tradeoff: a reliability mechanism changes the access pattern experienced by the material.

The derivation assumes rare independent accumulation, successful correction, and that scrubbing restores the relevant state. It does not describe errors that occur only during read, persistent defects that immediately reappear, or a burst that flips several bits at once. It also neglects errors introduced by scrub operations themselves. A controller cannot make every device reliable simply by scrubbing faster. The physical error mechanism determines whether the procedure addresses the problem or accelerates it.

For nonvolatile model-weight storage, scrubbing may be infrequent relative to reads. For a rapidly updated KV cache, ordinary writes may already refresh some states, while hot locations accumulate wear. A uniform background scrub schedule can spend bandwidth on recently written data and leave a heavily stressed region underserved. Tracking age and error history can improve allocation, but metadata reliability then becomes part of the design.

6.10 Logical addresses hide a physical allocation problem

A logical address identifies data from the program's perspective. A physical address selects an actual storage location. A mapping layer can move data while preserving logical identity, allowing bad-location replacement and wear spreading. The benefit requires bookkeeping: mapping tables, validity information, allocation state, and a recovery procedure after interruption. These are not free consequences of nonvolatility.

Suppose a logical overwrite cannot update its physical unit in place efficiently. A controller writes a new copy elsewhere, updates the map, and eventually reclaims old units. If a reclaimed block contains fraction $v$ valid data, retaining those data while creating $1-v$ new free fraction gives a simplified write-amplification factor $a_w=1/(1-v)$. At $v=0.2$ it is 1.25; at $v=0.8$ it is 5. This derivation is a block-reclamation teaching model. A byte-rewritable device with different update constraints may not need the same procedure.

Spare capacity can lower the valid fraction of selected reclamation victims and reduce write amplification, at the cost of usable density. A nominally denser multi-level array that needs more redundancy and spare space can deliver less useful capacity at a fixed lifetime target. Conversely, a less dense cell with predictable writes and stronger margins may simplify the controller. The comparison must include the physical operation granularity, not only bits per cell.

Wear leveling also interacts with locality. Moving a hot logical item among many physical locations spreads stress but may destroy a placement that minimized transfer distance. Static data can occupy much of the array, preventing hot writes from using those locations unless static wear leveling occasionally moves them too. That extra movement consumes energy and endurance. The ideal lifetime bound in the earlier section is therefore a benchmark for allocation efficiency, not a forecast.

6.11 Derive the concurrency needed to use the bandwidth

Let a memory interface sustain useful rate $R$ bytes/s, each independent transaction carry $S_b$ useful bytes, and average transaction latency be $L$ seconds. Little's law relates average in-flight transaction count $N$ to completion rate: $N=(R/S_b)L$. It follows from counting transaction-time accumulated in the system over a long interval. It requires a stable system and consistent arrival/completion boundaries, but not exponential service times.

For 80 GB/s of useful traffic, 64-byte transactions, and 100 ns latency, the average in-flight requirement is 125 transactions. A controller that permits only one such request at a time can supply at most 0.64 GB/s under those assumptions. This gap is independent of how fast the isolated ferroelectric polarization switches. Outstanding-request capacity, bank scheduling, reorder buffers, and interface width can be necessary to expose device parallelism to software.

The sixteen-word demonstrator intentionally accepts only one request at a time. Its purpose is to make acceptance, completion, reset, and fault semantics inspectable. It is not a high-bandwidth memory controller. Reusing its latency numbers as an architectural throughput model would be a category error. Chapter 7 derives its exact initiation interval and shows what would need to change to pipeline the service.

Bandwidth is also directional and granular. Read and write paths can share a bus, requiring turnaround cycles. A read-modify-write for a subword update can consume two transfers even if the application requested one write. ECC checking may require a whole codeword. Write verification can require several internal reads. The external payload rate and internal physical access rate are therefore different quantities; endurance depends on the latter while the application sees the former.

6.12 Nonvolatile bits do not make a transaction crash-consistent

Suppose updating a logical record requires writing its data and then its mapping entry. Power loss between those actions can leave a new data block with no pointer or a pointer to an incomplete block, depending on order. Nonvolatile cells preserve whichever partial state was reached. Correct recovery requires a protocol that distinguishes committed from uncommitted updates. A checksum can detect some corruption but does not by itself choose which version is authoritative.

A simple teaching protocol writes a new data version, verifies it, writes a commit record identifying that version, and only later reclaims the old copy. Recovery selects the latest valid committed version. This needs assumptions about write atomicity at some unit, ordering, durability of the commit record, and what failures can corrupt it. If those assumptions are not available from the hardware, software must add redundancy or a stronger protocol. The course's behavioral memory reset test does not establish any of these analog power-failure properties.

The architecture review spans sensing and organization proposals, while the vertical-NAND perspective motivates storage-scale possibilities. To connect either to an actual service, ask where the atomic write boundary lies, what reads return during an interrupted update, and which errors are exposed to the host. These questions do not diminish device research; they identify the missing engineering contracts required to turn it into a memory system.

1. Work backward from a service error budget

Use the earlier $10^{-15}$ protected-word target and independent single-error correction with 72-bit words. Estimate the allowed raw bit error and state the fragility of the result.

Solution. With $p_u\simeq2556p^2$, the raw target is $p\le\sqrt{10^{-15}/2556}\simeq6.26\times10^{-10}$. This is far smaller than the $10^{-5}$ demonstration value. It depends on independent identical errors and the code correcting every single error. Correlated bursts, decoder errors, or persistent bad bits require another analysis. A system can instead change code strength, retry policy, redundancy, or the allowed failure budget; it cannot claim that a weak raw-error example already meets the service target.

2. Trade scrubbing against endurance

Halve the scrub interval under the rare independent accumulation model. What changes, and when would the intervention be counterproductive?

Solution. The expected accumulated double-error count over fixed service time halves, while scrub traffic and scrub-induced writes double. If those writes dominate wear or create correlated damage, the benefit can reverse. Measure how errors depend on elapsed time versus access count before selecting an interval. The optimum must satisfy both data-integrity and lifetime constraints; minimizing one modeled error term alone is insufficient.

3. Explain why the same raw error can require a different code

Two arrays both report $10^{-5}$ average bit error, but one has independent faults and the other has row bursts. Can their redundancy be chosen from the same histogram?

Solution. No. Single-error correction depends on the probability of multiple errors in one codeword. A row burst can place many errors together even with a small marginal probability. Measure spatial correlations, then evaluate interleaving, erasure information, stronger codes, and spare rows against the burst model. The beta-binomial example demonstrates the sensitivity but does not model every row-burst geometry. Selecting a code from mean error alone discards the statistic the decoder most needs.

6.13 Turn the reliability lesson into a constrained design study

Choose a specific service before selecting redundancy. Suppose one delivered record contains $m$ protected words, each with uncorrectable probability $p_u$. If any uncorrectable word invalidates the record, the record-failure probability is at most $mp_u$ by the union bound. Under independent word failures it is exactly $1-(1-p_u)^m$. The distinction between a bit, word, record, and full computation changes the target by orders of magnitude. A reported raw bit-error rate cannot be compared directly with a request-failure requirement.

For a teaching record of 4 KiB and 64 useful bits per protected word, there are 512 words. With the independent example $p_u=2.55481\times10^{-7}$, the union bound is about $1.30806\times10^{-4}$ per record. That is already much larger than the word probability, before repeated accesses over service life. Applying the correlated within-word example makes the bound about 0.01207. The two results use the same mean raw bit error, which is why controller qualification needs the joint distribution.

A constrained study can enumerate candidate code families, spare fractions, scrub intervals, and mapping sizes. Each candidate needs a real code rate and correction/detection behavior, not an invented “corrects three errors” label with no redundancy cost. Evaluate useful capacity, residual failure, read/write overhead, and endurance separately. Reject candidates violating a hard requirement before comparing energy or area. If no candidate survives, report infeasibility and identify the requirement or physical mechanism that must change.

A retry policy can be another candidate, but its effect depends on why the first read failed. If errors are independent transient sensing noise, a second read can add information. If the stored state is permanently wrong or a shared reference is shifted, repeated reads can return the same wrong answer. Majority voting only has the familiar binomial improvement under an appropriate independence model. Extra reads also cost latency, energy, and possibly disturb. The device error mechanism determines whether retries are a remedy or a repeated observation of the same failure.

For three independent read decisions with individual error $p$, majority error is $3p^2(1-p)+p^3=3p^2-2p^3$. At $p=10^{-3}$ it is about $2.998\times10^{-6}$. If all three decisions share an identical wrong stored bit, majority voting leaves the error unchanged. These two limiting cases bound very different interpretations of a repeated-read experiment. Measure how errors repeat across time and bias before assigning the optimistic formula to an array.

A useful optimization objective needs a workload

Let fraction $f_w$ of logical operations be writes. If read energy is $E_r$, physical write energy is $E_w$, and write amplification is $a_w$, average dynamic energy per logical operation is $(1-f_w)E_r+f_wa_wE_w$, before maintenance not already included in $a_w$. A technology with expensive writes can still be attractive for a nearly read-only model store. The same device can be unsuitable for a frequently updated state buffer. The read/write mixture is part of the comparison, not a property of the memory alone.

Latency needs a separate mixture and tail analysis. Averaging fast reads and rare slow maintenance events may conceal unacceptable pauses. If reclamation, verification, or scrubbing blocks the read path, include those events in the service trace. If they run in the background, account for the bandwidth and power they consume. A controller can move work off the foreground path without making its resource cost disappear.

4. Compare a read-mostly and write-heavy role

Use synthetic $E_r=1$ nJ, $E_w=10$ nJ, and $a_w=2$. Compare average operation energy at write fractions 0.01 and 0.5.

Solution. At 1% writes, energy is $0.99(1)+0.01(2)(10)=1.19$ nJ. At 50% writes it is $0.5(1)+0.5(2)(10)=10.5$ nJ. The same physical memory has almost ninefold different average energy under the two access patterns. This arithmetic assumes the same access size and no additional background cost. It supports workload-specific placement, not a universal ranking of technologies.

6.14 Reliability project

Run python -X utf8 projects/stack.py reliability. Inputs are word length, raw bit error, state-window statistics, endurance, logical write rate, write amplification, and number of wear locations. Outputs are the exact binomial tail, its small-error approximation, a Gaussian sensing-error example, and ideal versus hotspot lifetime. The numerical tail is summed directly to avoid subtracting two probabilities almost equal to one.

For an optimization extension, enumerate redundancy choices and mapping sizes under a fixed usable-capacity constraint. Reject choices whose expected failure count exceeds the service budget. Report usable capacity, mean access overhead, and lifetime separately. A scalar “reliability score” would conceal which contract is being violated.

6.15 Exercises and solutions

5. A system-level error budget

A system performs $10^{12}$ protected-word accesses and allows at most $10^{-3}$ expected uncorrectable events. What per-access target follows?

Solution. Require $10^{12}p_u\le10^{-3}$, hence $p_u\le10^{-15}$. This is an expectation budget; translating it into a probability of any event requires additional reasoning or a bound. The synthetic $2.55\times10^{-7}$ example is far from this demanding target.

6. Write amplification penalty

What happens to ideal wear lifetime if write amplification rises from 2 to 5?

Solution. Lifetime scales inversely with amplification, giving a factor $2/5=0.4$. A more sophisticated controller can therefore reduce lifetime if its extra copying outweighs better wear distribution.

7. Same device, different placement

Why might Fe-NAND help model-weight storage without replacing the active KV cache?

Solution. Persistent weights can be stored and loaded in large blocks, while active KV state is updated repeatedly and read at latency-sensitive steps. Different access granularity, endurance, and bandwidth requirements apply. A storage benefit becomes a decoding benefit only if the architecture changes the critical data path and its costs are measured.

You can now translate a workload's lifetime and bandwidth requirements into device and controller constraints. Chapter 7 makes the transaction contract executable.
